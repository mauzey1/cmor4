Typed CV components
-------------------

``ControlledVocabulary`` is a coordinator over typed Pydantic components, not
a dictionary-like view of the source JSON. Its attributes expose the component
responsible for each kind of validation:

* ordinary scalar, list/regular-expression, mapping, and template definitions
  use a generic ``AttributeRule``;
* ``license`` uses a ``LicenseComponent`` that owns the license catalog and
  template rendering;
* ``source_id``, ``experiment_id``, and ``institution_id`` use catalog
  components that expose the selected entry for cross-field defaulting and
  validation;
* ``source_type`` uses a component for both project-wide token membership and
  experiment-specific required/optional component combinations;
* ``cv.drs`` contains typed directory and filename templates;
* ``cv.frequency``, ``cv.forcing``, and ``cv.tracking_id`` own their
  specialized parsing and validation rules;
* scalar, singleton-required, and selected nested defaults are collected by a
  ``cv.defaults`` component;
* project-specific attributes are available as generic rules in ``cv.rules``.

For example, allowed activity identifiers are available through
``cv.rules["activity_id"].allowed_values`` and a literal project license is
available through ``cv.license.default_text``. Runtime values such as
timestamps and UUIDs are generated by ``ControlledVocabulary`` using the
typed default and tracking components.

This keeps the dataset creation API unchanged while making CV behavior
discoverable through named, typed attributes.
